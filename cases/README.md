# Каталог тест-кейсов

В `cases/` хранятся рабочие тест-кейсы. Это источник истины проекта: таблицы используются для импорта, а результаты выгрузки не заменяют Markdown-файлы.

## Структура

- первый уровень после `cases/` — продукт, например `crm`;
- вложенные папки — путь функционального раздела;
- в конечной папке находятся `section.json` и групповой Markdown-файл;
- каждый блок внутри Markdown-файла — отдельный тест-кейс с числовым ID.

Например:

```text
cases/crm/listings/clients/
├── section.json
└── листинг клиенты.md
```

Имя группового файла строится по первому и последнему элементам пути: `листинги/клиенты` превращается в `листинг клиенты.md`.

## Создание раздела

Сначала проверьте существующие разделы:

```bash
qa-cases sections
```

Если нужного раздела нет, создайте его:

```bash
qa-cases create-section \
  --product credit-booster \
  --path demo/sample-section \
  --name "Тестовый раздел" \
  --id-prefix CB-DEMO \
  --alias "Пример раздела"
```

`--id-prefix` используется для технической идентификации раздела. ID самих тест-кейсов всегда числовые.

После изменения каталога выполните:

```bash
qa-cases validate
make test
```
