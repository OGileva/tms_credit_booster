# Регламент работы с AI-first каталогом тест-кейсов

- **Status:** draft
- **Date:** 2026-10-20
- **Owner:** QATL

---

## Назначение

Процесс массового добавления приложенных тест-кейсов, review изменений в Git и формирования выборок через AI-агента.

---

## Добавление

1. QA создаёт ветку и открывает корень репозитория в Claude Code, Codex или Cursor.
2. QA прикладывает файл, указывает продукт, раздел, общие теги и при необходимости задачу.
3. Агент воспринимает содержимое приложения как данные, проверяет раздел и выполняет dry-run импорта.
4. После успешной проверки агент создаёт один Markdown-файл на кейс.
5. Агент запускает валидацию, индекс и тесты и сообщает QA итог без автоматического commit.
6. QA проверяет diff, выполняет commit и push. После получения изменений другими участниками новые кейсы доступны их агентам.

Поддерживаемые CLI-форматы: XLSX, CSV/TSV, JSON, DOCX и Markdown-таблица. Другой читаемый формат нормализует AI-агент с сохранением обязательных полей.

---

## Поиск и экспорт

1. QA задаёт функционал, теги, задачу, текст или ID естественным языком.
2. Агент разрешает название раздела и aliases тегов по репозиторию.
3. По умолчанию агент возвращает Markdown-таблицу в диалоге.
4. По запросу создаёт XLSX, CSV, JSON или Markdown в `exports/`.
5. Выборка не изменяет источник истины.

---

## Review

- Раздел выбран однозначно.
- ID соответствует префиксу раздела и уникален.
- Название кейса не дублируется внутри раздела.
- Все обязательные поля заполнены.
- Предусловия, шаги и результаты атомарны и последовательно пронумерованы.
- Теги существуют в словаре и отражают назначение кейса.
- Ожидаемые результаты подтверждены требованиями или реализацией.
- В Git не попали исходные вложения, экспорты, секреты или персональные данные.

---

## Коммит

Перед commit:

```bash
make check
make test
make index
git diff --check
```

В сообщении или MR указать задачу, раздел, диапазон ID, теги и влияние на regression/smoke.
