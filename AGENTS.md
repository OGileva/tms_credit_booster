# AGENTS.md — qa-tests

Репозиторий тест-кейсов QA. Excel-файлы в `cases/` — источник истины; `generated/index.json` — производный индекс для поиска и анализа.

---

## Как начать

1. Прочитать этот файл.
2. Прочитать [`CONTEXT.md`](CONTEXT.md) и [`README.md`](README.md).
3. Перед работой в `cases/` или `suites/` прочитать локальный `AGENTS.md` папки.
4. Для добавления кейсов использовать [`_templates/test-cases.xlsx`](_templates/test-cases.xlsx).
5. Перед коммитом выполнить `make check` и `make index`.

---

## Канон тест-кейса

- Формат хранения и выдачи: таблица Excel `.xlsx`.
- Один файл содержит один лист `Тест-кейсы`.
- Разрешены только пять колонок в указанном порядке: `Name`, `Description`, `Preconditions`, `Steps`, `Expected Result`.
- `Name` начинается со стабильного ID: `CB-<КОД_ФУНКЦИИ>-<NNNN> — <понятное название>`.
- ID не меняется при переносе или переименовании кейса.
- `Preconditions`: нумерованный список атомарных действий; прошедшее время; совершенная форма; безличная формулировка; без слова «был/была».
- `Steps`: нумерованный список атомарных действий; безличная формулировка; отвечает на вопрос «что сделать?».
- `Expected Result`: нумерованный список; безличная формулировка; отвечает на вопрос «что произошло?»; настоящее время, совершенная форма.
- Названия из кода переводятся на человекочитаемый русский язык.
- Если пользователь не задал количество для генерации нового набора, подготовить не менее 20 кейсов.
- Применять классы эквивалентности, граничные значения, попарное тестирование, переходы состояний и таблицы принятия решений там, где они подходят.

## Достоверность

- Не придумывать поведение системы, API, роли, статусы, данные и ограничения.
- Перед созданием кейсов сверять требования и актуальную реализацию. Путь к реализации задаётся в конкретной задаче; этот репозиторий его не подменяет.
- Если факта нет в требованиях или коде, оформить вопрос или риск, а не превращать предположение в ожидаемый результат.
- Изменение файла или компонента — основание включить проверку в регресс, но не доказательство runtime-поведения.
- Не хранить секреты, персональные или продуктивные данные.

## Структура

| Путь | Назначение |
|---|---|
| `cases/<product>/<function>/` | Исходные XLSX-пакеты по продукту и функционалу |
| `suites/` | Правила наборов: smoke, release-critical, full-regression |
| `_templates/` | Шаблоны для массового добавления |
| `regulations/` | Процесс совместной работы |
| `qa_cases/` | CLI для проверки, индекса и выборок |
| `generated/index.json` | Производный текстовый индекс; вручную не править |
| `exports/` | Локальные выгрузки; не коммитить |

---

## Правила изменений

- Новый функционал создаётся командой `qa-cases new-pack` или копированием шаблона в правильный путь.
- Один кейс хранится ровно в одном исходном XLSX. Наборы в `suites/` содержат правила и ID, а не копии кейсов.
- При изменении структуры папки сразу обновить её `README.md` и `AGENTS.md`.
- `generated/index.json` обновлять только командой `make index`.
- Не коммитить содержимое `exports/`, `.venv/`, временные файлы Excel `~$*` и кэши Python.

---

## Критерий готовности

1. `make check` завершён без ошибок.
2. `make test` завершён без ошибок.
3. `make index` обновил индекс.
4. Выборка по затронутому функционалу или suite выгружается в XLSX с пятью каноническими колонками.
